O mural de empregos de Northbridge lista 27 vagas em uma página contínua. O proprietário quer que o 
endpoint de listagem dê suporte a uma caixa de pesquisa e paginação, como qualquer site de empregos. 
O GET /jobs inicial retorna todos os empregos, sem filtros e sem paginação, a partir de data/jobs.json. 

Requisitos 
Estenda GET /jobs?search=&page= para que responda com 200 contendo os dados mais um bloco meta: 

{ 
} 
"data": [ { "id": 1, "title": "...", "company": "...", "location": "...", "salary": 68000 } ], 
"meta": { "total": 27, "page": 1, "per_page": 10, "total_pages": 3 } 

1. Pesquisa — quando search for fornecido, mantenha apenas os empregos cujo título ou empresa contenha 
o termo (substring insensível a maiúsculas/minúsculas). Pesquisa vazia/ausente = todos os empregos. 
2. Paginação — 10 por página; a página assume o padrão 1. 
3. Meta — cada resposta inclui meta: total (contagem 
correspondente), page, per_page (10), total_pages (arredondamento para cima de total / 10, mínimo 1). 
4. Combinado — pesquisa e paginação funcionam juntas (a paginação se aplica ao conjunto filtrado). 
5. Fora do intervalo — uma página posterior à última retorna um array de dados vazio com meta ainda válido. 

Restrições 
• Sem frameworks ou dependências — apenas PHP puro ou Node http puro. 
• Todas as respostas em JSON; mantenha o 404 do código inicial para rotas desconhecidas. 
• Os arquivos da API Bruno são fornecidos.
